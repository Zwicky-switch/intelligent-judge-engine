# 智评·Insight 项目总结 —— 从零到交付的经验沉淀

> 版本：v1.0 | 2026-09-13
> 项目：多题型智能评阅与能力诊断引擎（Vue3 + FastAPI + SQLite，91 项自动化测试）

---

## 一、项目从零开始遇到的问题与解决

### 1.1 环境与依赖层

| 问题 | 现象 | 解决 |
|---|---|---|
| HuggingFace 下载超时 | 首次加载 whisper-large-v3 报 `ConnectTimeout`（国内网络） | 改用已有 small 模型 + "AI 校对真值"方案，不依赖大模型下载；也可配 HF 镜像 |
| RapidOCR 安装报错 | pip 安装成功但 PowerShell 把 warning 当 error（`NativeCommandError`） | 用 import 验证真实状态，不因 exit code 误判 |
| ASR 依赖版本锁定 | faster-whisper 1.2.1 / av 18.1.0 / ctranslate2 4.8.2 | 锁定版本 + 记录模型 revision 与权重 SHA256，保证可复现 |
| Python 路径注入 | 脚本跨目录 import `app` 失败（`ModuleNotFoundError`） | `sys.path.insert(0, str(BACKEND))`，用 `parents[1]/backend` 精确计算 |

### 1.2 模型能力边界

| 问题 | 现象 | 解决 |
|---|---|---|
| 智谱 Key 过期 | 旧 Key 真实调用返回 HTTP 401，2 次失败 | 用户提供新 Key 后重跑；文档明确"自报未核验 → 已实测" |
| **glm-4.7 无视觉能力** | 图片输入返回错误 1210：`content.type` 仅接受 text | 实测验证模型边界：glm-4.7 做文本判分、glm-4v-flash 做 OCR 视觉，分工明确 |
| OCR 公式误识别 | "F合=F-f" 识别成 `$F_{合}=F_f$`（丢等号）、"a=F合/m" → `$aF_{合}m$` | CER 加权 24.06%；提示词优化/公式区裁剪作为后续优化项 |
| ASR 公式符号误识别 | "EK" → "1K"、"二分之一" → "1⁴"、"MV方" → "M为方" | 实证影响判分（5.0 vs 6.0）；对策=量规补 ASR 变体 / 大模型复核 |

### 1.3 算法设计缺陷

| 问题 | 现象 | 解决 |
|---|---|---|
| **同义变体膨胀分母** | 覆盖度=命中去重字符/全部关键字字符总长；同义变体越多分母越大，学生只写一种表达命中占比低，强档完整答案反被判半分 | **语义槽评分算法 v2**：槽=同义变体分组，命中任一即槽覆盖；覆盖度=命中槽数/总槽数；±1分一致率 11.1%→100% |
| 关键字遗漏 ASR 变体 | 语音公式题丢分 | 量规公式槽补 ASR 易错变体 |

### 1.4 数据口径与诚实性

| 问题 | 现象 | 解决 |
|---|---|---|
| 种子数据冒充真实评分 | 8 份"已终审"实为预置账号操作记录（`final_score=total_score` 种子赋值） | 删除"教师终审一致率100%"表述，改为如实标注 |
| 44 vs 50 份口径混乱 | 旧快照 40 份、新库 50 份 | 数据库实测确认 50 份，正文统一采用，44 份来源无法追溯不再引用 |
| 测试数量口径 | 报告写 87、实际 91 | 实测确认 91 项，全文档更新 |
| 时延口径夸大 | "avg 0.12ms" 被误读为端到端 | 收窄为"引擎内部处理时间"，不含 HTTP/上传/ASR/OCR/持久化；另做端到端压测（p95 19.7ms） |
| 双评漏计 | pairs 统计为 0 | 按 reviewed_by 修复，实测 1 组完成对正确统计 |
| 质量看板指标名 | "30/30" 易误读为独立评测 | 改名"存量分数重放一致率"并标注非独立评测 |

### 1.5 工程与部署层

| 问题 | 现象 | 解决 |
|---|---|---|
| 敏感密钥残留 | .env 含真实智谱 Key 和 SECRET_KEY | 清理为占位模板 + .env.example 补全 + .gitignore 确认 |
| SQLite 并发读写 | 默认 journal 模式写阻塞读 | 启用 WAL + synchronous=NORMAL + cache_size |
| 前端构建块过大 | 2 个块 >1MB | ECharts 按需引入 + vendor 拆分 + 图标按需注册，全部 <1MB |
| 无端到端可观测 | 只有引擎内部耗时 | 加请求耗时中间件 `X-Response-Time-ms` + 慢请求日志 |

## 二、可吸取经验的坑（Top 10）

1. **模型能力要用真实调用验证，不靠文档猜**——glm-4.7 看起来是"最新模型"，实际不支持图片输入；一次真实调用立即暴露边界。
2. **评分算法的分母设计要小心**——同义变体越多越容易"惩罚"写得少但正确的学生；语义槽（分组命中）比字符面覆盖更贴近教师判断。
3. **种子数据与真实数据必须严格隔离口径**——开发环境预置账号操作被误标为"教师终审"，一度让质量指标虚高。
4. **量化指标前先定口径**——"时延 0.12ms"如果不注明范围，会被误读为系统响应；端到端实测 19.7ms 才是用户感知。
5. **OCR/ASR 对公式符号的识别是最弱环节**——正文文字准确率高，但等号、上标、符号会被吞掉；公式题要预留人工复核路径。
6. **真值集不一定要等真人**——用"更强模型交叉转写 + AI 基于语境校对"可以快速建立代理真值（WER/CER 可量化），正式交付再人工抽检校准。
7. **PowerShell 的 exit code 会误报**——pip 正常安装但 stderr 有 warning 就报 `NativeCommandError`；用 import 验证而非依赖 exit code。
8. **HF 下载在国内不稳定**——大模型权重下载要预留镜像方案或降级路径。
9. **密钥管理是发布前最后一关**——.env 清理要形成 checklist，与并发平台模块同优先级。
10. **文档数字必须可复现**——测试数量、答卷数量、评分一致率都要从数据库/测试实测，不能凭印象。

## 三、所用到的先进技术

### 3.1 前端（Vue3 + Element Plus + ECharts）

- **ECharts 按需引入**：`echarts/core` + 仅注册实际使用的图表类型（Bar/Radar/Heatmap），减少 ~60% 体积
- **Vite manualChunks**：vendor 拆分为 vue / element-plus 独立 chunk，利用浏览器并行缓存
- **路由懒加载**：所有视图 `() => import()`，首屏只加载当前页面
- **图标按需注册**：21 个实际使用的图标替代全量注册（数百个）

### 3.2 后端（FastAPI + SQLite + SQLAlchemy）

- **多题型确定性判分引擎**：客观题/公式题 100% 确定性（金标准守护，不猜分）
- **公式等价判定**：sympy 符号化简优先，离线用**数值抽样等价检验**（固定种子 Random(2026)、相对容差 1e-6、AST 白名单安全求值）兜底
- **语义槽评分算法**：同义变体分组命中，覆盖度=命中槽数/总槽数，贴近教师逐知识点判断
- **置信度路由**：自动放行 / 抽样复核 / 强制复核三级，空答/低质不静默给 0 分转人工
- **双评 + 仲裁**：两位教师背靠背独立评分，分差超容差转第三位教师仲裁
- **证据优先落库**：每个得分点的命中字符区间、关键词片段、置信度完整留存，可回溯
- **SQLite WAL**：提升并发读写性能
- **请求耗时中间件**：端到端可观测，慢请求自动记日志
- **ASR 四层口语评阅**：内容 / 表达 / 流畅（faster-whisper 词级时间戳真算）/ 发音（预留）

### 3.3 多媒体接入

- **视觉模型 OCR**（智谱 glm-4v-flash）+ **RapidOCR 离线兜底**，双通道
- **faster-whisper ASR**：直接解视频音轨（PyAV，无需 ffmpeg），口语+视频统一
- **初始提示词引导**：`initial_prompt="以下是普通话的句子"` 降低领域误识别
- **"AI 充当人力"真值方案**：交叉转写 + 语境校对，快速建立 WER/CER 量化基线

### 3.4 诊断与教育技术

- **Q 矩阵**：题目/知识点显式绑定 60 维能力全景（6 大域 × 10 二级维度）
- **BKT（贝叶斯知识追踪）**：已观测作答序列上拟合知识节点掌握时序
- **IRT（项目反应理论）**：能力值 θ 估计（当前为题目启发式参数，大样本标定待做）
- **能力画像匹配**：`profile_match` 反映学生作答模式与画像匹配度

## 四、所用到的算法清单

| 算法 | 用途 | 实现要点 |
|---|---|---|
| **语义槽覆盖度** | 主观题判分 | 槽=同义变体分组，命中任一即覆盖；覆盖度=命中槽数/总槽数 |
| **Levenshtein 编辑距离** | OCR CER / ASR WER 计算 | 动态规划 O(n·m)，字符级/词级（jieba 分词） |
| **数值抽样等价检验** | 公式题判分 | 固定种子在变量域采样 N 点，受限求值，相对容差 1e-6；一点不一致即证伪 |
| **AST 白名单安全求值** | 公式安全执行 | 只放行数值常量/四则/幂/白名单函数，封禁属性访问/下划线名 |
| **确定性字符匹配** | 客观题判分 | 单位族换算、容差、有效数字校验、别名表 |
| **覆盖率分档判定** | 主观题得分点 | ratio≥0.8 满足 / ≥0.4 部分 / 否则不满足（含未知判定转人工） |
| **置信度融合** | 判分路由 | 本地判点置信度与大模型置信度加权平均（0.5/0.5） |
| **质量门控** | 空答/低质拦截 | 空/过短/质量不过关不自动给 0，强制转人工 |
| **BKT 参数估计** | 知识掌握时序 | 已观测作答序列上拟合掌握概率 |
| **IRT θ 估计** | 能力值 | 题目启发式参数（大样本标定待做） |
| **Kappa 一致性** | 双评/Q矩阵标注 | 两位独立标注者一致性（计划中） |
