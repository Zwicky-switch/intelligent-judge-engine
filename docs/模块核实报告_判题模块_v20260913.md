## 一、模块概述

本模块已有真实工程交付（判题小组·刘奕飞，交付物"智评·Insight——多题型智能评阅与能力诊断引擎" 0.1.0，FastAPI+SQLite 后端／Vue3+Element Plus+ECharts 前端，附完整 README 与架构说明文档）。

### 1.1 题型覆盖与判分方式

系统覆盖 **8 类题型**：单选、多选、判断、填空、数值、文本主观、公式（符号与数值抽样等价判定）、口语。

- **客观题与公式题**：走确定性规则引擎判分，不引入生成式模型参与最终分数计算；空答/无法解析不静默判 0、一律转人工复核。
- **文本主观题与口语题**：按量规逐得分点召回原文证据后判定，产出带字符级证据的分数。
- **可插拔外部大模型**：可接入 DeepSeek/通义/智谱等外部大模型对量规判点做复核和生成中文评语；模型只能在量规约束内复核、不能绕过量规改分。
- **离线可用**：未配置外部模型 API Key 时，由内置本地启发式引擎完成判分，全流程无需外部 Key 也可离线跑通。

### 1.2 双评与仲裁

- 可配置为"双评题"的题目由两位教师背靠背独立评分，分差在容差内自动取均值终审，超差则转第三位教师仲裁。
- 量规和答案的正式发布可配置"双人复核"，需两个不同账号确认后才生效。
- 每次教师操作（接受/改分/仲裁/退回）都写入复核记录与不可删除的审计日志。

### 1.3 能力诊断

- 系统内置 **6 个一级能力域 × 10 个二级维度 = 60 维能力体系**（超过命题要求的"≥50 个维度"）。
- 通过知识点到维度的映射矩阵，把客观题得分和主观题量规分项汇入节点掌握度、BKT 时序掌握度和"画像-作答匹配度"计算。
- **注意**：60 维是结构数量，不等同于诊断结果已达到命题要求的匹配度。

## 五、关键口径更正

### 5.1 教师一致性表述已更正

此前汇报所称"机器评分与教师终审一致率 100%（n=5）"来自种子脚本执行 `final_score=total_score`，不是真实教师评分；这 5 份记录没有对应的真实评阅明细或评阅教师。

**团队已同意删除该一致率及由同一复制关系得到的校准参数（a=1、b=0、r²=1）**，本报告改为如实标注"开发环境演示复核数据，非真实教学场景教师评分，待真实教师盲评后补充"。

### 5.2 双评统计漏计已修复

此前数据库中一组 grader 与 grader2 均给 4.0 分的双评记录，因代码把"两个分数是否不同"误当成"是否有两位教师"而被误报为 0 组。

团队已按 `reviewed_by` 字段修复统计逻辑（`backend/app/api/metrics.py::_double_teacher_consistency`），覆盖三类边界：
1. 同分计入一致
2. 同一教师重复操作只取首次记录
3. 单题被评阅超过两次只取前两位教师

新增 4 个边界测试用例，后端测试从 87 项增至 91 项、全部通过。修复后正确统计为 **1 组双评完成对、±1 分一致率 1.0**。

### 5.3 客观题指标更名

质量看板中的客观题指标已由团队改名为 **"存量分数重放一致率"**（30 个样本、0 不一致），界面文案同步说明：
- 这是同一引擎对自身历史评分进行重放对账（对全部自动放行客观分用当前引擎重放核对总分，不一致计入 misgraded）。
- **不是独立冻结真实题库与人工答案的评测结果。**
- 独立评测**尚未开始（NOT_RUN）**。

### 5.4 时延口径收窄

库存 0.02 至 1.04 毫秒的时延：

## 六、OCR 能力（2026-09-13 已实测验证）

### 6.1 当前状态

- **2026-09-13 用户提供有效智谱 Key，OCR 真实调用已跑通**：glm-4.7（用户指定）纯文本调用 HTTP 200 验证 Key 有效；但 glm-4.7 **不支持图片输入**（返回错误码 1210：content.type 仅接受 text），故 OCR 改用智谱视觉模型 **glm-4v-flash**，图片输入 HTTP 200 并正确识别手写解题过程。
- 4 张真实学生手写图片（同学1/同学2 各 2 张，受力分析题 + 机械能守恒题）全部识别成功。
- 本地 RapidOCR 兜底已安装（rapidocr-onnxruntime 1.4.4），未配置 Key 时自动回退离线识别。
- 生产数据库不含 zhipu-mock 记录，mock 仅存在于测试代码路径，不影响正式数据统计。

### 6.2 真实调用与 CER 评估

2026-09-13 用有效 Key 完成 4 张真实学生原图 OCR，建立人工逐字真值后计算 CER：

| 图片 | 识别字数 | 编辑距离 | CER |
|---|---|---|---|
| student1_q1（同学1 受力分析） | 171 | 58 | 46.77% |
| student1_q2（同学1 机械能守恒） | 53 | 0 | **0.00%** |
| student2_q1（同学2 受力分析） | 152 | 16 | 10.74% |
| student2_q2（同学2 机械能守恒） | 83 | 22 | 30.14% |
| **汇总** | **459** | **96** | **平均 21.91% / 加权 24.06%** |

- **正文文字识别良好**：机械能守恒题（student1_q2）CER=0%，逐字正确。
- **公式域误差集中**：受力分析题 CER 较高，主要错在公式符号——OCR 将 "F合=F-f" 错识为 "$F_{合}=F_f$"（丢等号）、"a=F合/m" 错识为 "$aF_{合}m$"（丢等号与斜杠）、"f=μN" 部分符号错位；数学公式的上下标/等号/分数线是当前主要误差来源。
- 评估脚本与真值已落地：`scripts/ocr_eval/`（eval_ocr_cer.py、batch_ocr.py、test_zhipu_model.py、samples/、ground_truth/、results/）。

### 6.3 结论

**智谱 OCR 已真实跑通并完成量化评估（2026-09-13）**：加权 CER 24.06%，正文识别良好、公式域需改进。glm-4.7 无视觉能力，OCR 使用 glm-4v-flash（已实测 HTTP 200）。公式识别误差可通过优化 OCR 提示词（要求保留等号/斜杠）或公式区裁剪进一步提升，属优化项而非阻断项。

## 八、风险清单（按优先级）

### 高优先级

1. **无真实教师评分数据**：现有 8 份已终审为开发环境预置账号操作，非真实教师盲评结果。真实教师盲评需项目负责人协调任课教师参与。

3. **OCR 真实效果已验证但公式域 CER 偏高**：2026-09-13 已用有效 Key 实测，加权 CER 24.06%（正文良好、公式符号误差集中），可通过提示词优化/公式裁剪降低，属优化项。

### 中优先级

4. **ASR 已有代理真值但需人工抽检**：2026-09-13 用"AI 充当人力"方案建立 5 段真实素材的校对真值，WER 16.95%/CER 7.29%（同音字/公式符号误差为主，公式类误识别影响判分已实证）；正式交付仍需人工抽检 ≥10% 校准。
5. **四项实验责任人待定**：教师盲评、能力诊断信效度、Q 矩阵标注一致性、IRT/BKT 大样本标定均待指定责任人和时间点。
6. **客观题测试集未独立隔离**：47 样例由开发团队编写，非独立冻结真实题库评测。
7. **时延口径易被误读**：引擎内部处理时间（0.12-1.04ms）不含 HTTP/上传/ASR/OCR/持久化，不能表述为端到端响应时间。

8. **前端依赖漏洞**：1 高危（vite≤6.4.2）、2 中危（esbuild≤0.24.2、echarts<6.1.0 XSS），需破坏性版本变更，已评估暂缓。
