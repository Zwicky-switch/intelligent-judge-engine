# 智评 · Insight —— 交付包阅读与观看方案

> 适用对象：组长 / 评审团队 / 接手团队
> 配套版本：交付版 v1.1（演示基线 `insight-judge-v0.1`）
> 本文档告诉你：**按什么顺序读什么、按什么顺序看什么、如何自己验证**。全部内容 5 分钟可速览、30 分钟可评审、2 小时可完整验证。

---

## 一、总览：交付包里有什么

```
intelligent-judge-engine/                    ← 交付根目录（整个文件夹）
├── README.md                                ← 项目入口：定位、启动、核心设计、组长问题与解决方案
├── .env.example                             ← 环境变量模板（交付版不含真实密钥）
├── docker-compose.yml / LICENSE / .gitignore
├── backend/                                 ← FastAPI 后端（91 例测试、引擎、诊断、API）
├── frontend/                                ← Vue3 前端（5 角色工作台，构建 <1MB）
├── deploy/                                  ← 生产部署（nginx.conf + PRODUCTION.md）
├── docs/                                    ← 全部文档（见下方阅读路线）
└── scripts/                                 ← 一键启动 + 4 组评估脚本与真实结果
```

## 三、观看路线（系统演示，建议录屏）

### 3.1 启动（2 分钟）

1. 双击 `scripts/start_all.bat`（一次启动前后端）
2. 浏览器自动打开 **http://127.0.0.1:5173**（若未自动打开请手动访问）

> ⚠️ 不要直接双击 `frontend/index.html`——必须以开发服务器方式访问（file:// 会白屏）。

### 3.2 九屏演示顺序（建议录屏，约 8 分钟）

按交付汇报第 4 节列出的评审看点，按此顺序录制：

| # | 画面 | 登录账号 | 操作 | 评审看点 |
|---|---|---|---|---|
| 1 | 命题与发布 | `prop_teacher` / `teacher123` | 题库 → 新建/编辑 → 发布（双人复核） | 量规/答案编辑器、版本快照与差异比较 |
| 2 | 自动判题（客观即时） | `student_li` / `stu123` | 学生自主练习 → 提交客观题 | 秒级给分 + 证据高亮 + 原因回溯 |
| 3 | 主观/公式/口语送复核 | `student_li` | 提交主观文本/公式/口语 | 逐得分点判定 + 证据召回 |
| 4 | 强制复核队列 | `grader` / `teacher123` | 阅卷工作台 → 复核中心 | 空答不静默给 0、转人工 |
| 5 | 双评仲裁全流程 | `grader` → `grader2` → 第三教师 | 复核中心双评题分组 | 独立评分、±容差取均值/超差仲裁 |
| 6 | 学生查分与证据展开 | `student_li` | 我的成绩 → 展开得分 | Evidence 原文区间/媒体侧车回放 |
| 7 | 诊断报告 | `student_li` | 能力诊断报告 | 六域雷达 + 60 维全景 + BKT 时序 + 短板与建议 |
| 8 | 教务看板 | `admin` / `admin123` | 质量看板 | 重放一致率/时延/校准/班级画像 |
| 9 | 引擎技术导览 | 任意 | 侧边栏 `/engine` | 处理闭环一页讲清 |

**演示要点**：
- 第 5 屏双评：分别以 `grader`（第 1 评）与 `grader2`（第 2 评）登录对同一道双评题打分，看均值/仲裁流转
- 第 7 屏诊断：观察六域雷达形状与短板 Top3 是否与三档学生（强 student_li / 中 student_wang / 弱 student_zhao）预期一致
- 第 6 屏媒体回放：找图片/语音/视频作答的卷子，验证原图/原录音/原视频回放

## 五、评审红线（必须如实告知组长的事项）

1. **无真实教师盲评**：演示库 8 份"已终审"为预置账号操作记录；引擎 vs 教师一致率 100% 是**模拟教师二审**（关键字对照法）结果，非真实教师评分；真实教师盲评待协调任课教师。
2. **OCR/ASR 真值为替代基准**：CER 24.06%、WER 16.95%/CER 7.29% 基于"AI 校对代理真值/人工逐字校对"，**非真人听写**；正式交付需人工抽检 ≥10% 校准。
3. **演示数据非真实学生**：50 份答卷由种子脚本生成（38 份自动生成 + 迁移），可用于功能走查，不能作为真实教学效果数据集。
4. **时延口径**：看板 0.12ms 为**引擎内部处理时间**；端到端 p95 19.7ms 才是用户感知。
5. **判分模型**：交付版不含真实 Key，未配置时走本地内置引擎（功能完整）；配置 `GRADE_LLM_*` 后升级为「规则定分 + 大模型复核」协同模式。

## 六、需要真实人力才能完成的后续事项

| 事项 | 阻塞点 | 建议 |
|---|---|---|
| 真实教师盲评（≥20 卷/题型） | 需项目负责人协调任课教师 | 可用 `scripts/teacher_sim/` 的方案扩量 |
| ASR 真值人工抽检校准（≥10%） | 需人工听写 | 用 `scripts/asr_eval/ground_truth/` 模板 |
| IRT/BKT 大样本标定 | 需真实题库作答数据 | 系统已产出 60 维诊断，数据积累后即可标定 |
| Q 矩阵标注一致性（Kappa） | 需两位独立标注者 | 命题教师 + 第二位教师背靠背标注 |
